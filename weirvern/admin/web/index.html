What is new. Calibration and the shadow channels below are read-only experiments: they measure budgets, candidates and regime changes, but no shadow row can create or change an alert.

What writes it. Each retrain folds in the newest samples from this deployment's own traffic.

Last changed. Check freshness above — a model scored against a stale baseline is still confident.

Where to see it. This table; and any anomaly the baseline helped score carries its name under Models on the row.

    Domain Gate

    What it is. The DNS half of enforcement: a name on an enabled blocklist, or a block-mode domain rule, is answered with a block answer. It needs no nft rules and keeps working while the Traffic Gate is disarmed.

    What writes it. The blocklist sync and the operator's domain rules; the switch below gates the domain half only.

    Last changed. Each change is an audit row; each hit is recorded in Blocks.

    Where to see it. Hits appear in Blocks with the name that matched. Blocklists and their switches live on the Settings tab.

    Answers DNS queries. Independent of the Traffic Gate.

    Traffic Gate

    What it is. The packet half of enforcement: nft rules on the capture interface that drop traffic. It fails open on purpose — if its supervisor dies the gate OPENS rather than taking your network down.

    What writes it. Operator blocks, plus the ensemble policy where you have opted in.

    Last changed. Every block and expiry is an audit row.

    Where to see it. The state line below says whether the kernel is enforcing; the fleet table says which segment each gate covers.

    Blocking on detections

    What it is. Whether the ensemble's own verdicts may block. Off by default: a tool that starts blocking on model output the moment it is installed would surprise anyone who installed it to watch first.

    What writes it. The operator — this policy is the trust boundary.

    Last changed. Each change is an audit row, and each level states what it costs.

    Where to see it. Blocks made this way appear in Blocks and the audit with the threshold as their reason.

    New rule

    Domain rules are answered in DNS by the Domain Gate; address rules are dropped by the Traffic Gate.

    What it is. The safety refusals — on purpose: a rule that blocks the wrong thing takes a network down, so a rule with no address, a port without a protocol, the management interface, this weirling's own address, and anything covering the whole internet are refused.

    What writes it. The gate's validator, at submit time.

    Last changed. Nothing is stored — a refusal happens before anything exists.

    Where to see it. The message right here when a rule is refused; each refusal names its fix.

    Blocks

    What it is. The recorded-block ledger: what a device asked for, which rule or blocklist matched, and what the gate did. It is a drill from Sluice Gate, not a separate rules surface.

    What writes it. DNS rules and imported lists, plus the DNS traffic that meets them. The rule itself is edited in Sluice Gate.

    Last changed. Hits append as devices ask for listed names.

    Where to see it. Here; the rules that produced them live in Sluice Gate.

    Scan Network

    Sonar measures the segment and fills the network, gateway, and a free intercept IP. Review them, then stage this interface.

    Sonar surveys the network this sensor's capture interface is on — it reads the segment, sends one ARP sweep to find which addresses answer and which are free, checks the gateway — and reports what it measured. Nothing is written; enabling siphon uses what Sonar found when it runs.
    A test run switches the sensor to siphon mode for 30 seconds, lets the worker run the real intercept, then switches back to loch — the mappings are restored on the worker's normal shutdown path. It needs the siphon capabilities on the sensor node and a complete plan. The result below says which hosts were intercepted, and that the mode was put back.
