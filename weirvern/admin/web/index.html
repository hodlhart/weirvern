What it is. A ripple is one host and one hour in which several independent measurements moved together, each against that host's own trailing history. The sentence on the row names the channel, the value, the baseline median it was ranked against, the scale, and the p-value over the number of baseline windows behind it.

What the score is. The joint surprise of the supporting families: the sum of -log10(p), one p-value per family. Two families at 0.01 score 4.0; one family at 0.001 scores 3.0. It is a ranking bar, not a probability, and this page never pages on it.

What writes it. The ripple evidence pass, every hour. The grouping is deterministic: a ripple is not stored, it is read from the evidence rows it is made of.

Where to see it. Click any row for one line per channel with its scale, family, value, baseline and p-value — then the host's model anomalies in the same window, labelled as corroboration.

Model anomalies corroboration, not the finding

The model's fused-score detections across this window. A model alone is usually noise; these corroborate a ripple, and they are never the ripple itself.

What it is. Host-windows the ensemble flagged: the score that crossed the line, and which detectors agreed on it — one model alone is usually noise, so agreement is the signal worth reading first.

Why it is here. These are corroboration for the ripples above. A model anomaly can support a ripple; it cannot create one, outrank one, or replace its measured evidence.

What writes it. The detector ensemble, every scan window.

Last changed. New rows land as windows complete; a reviewed row keeps its verdict.

Reading a row. The count is just the number of distinct windows with the same verdict. Click the count to list every occurrence.

Where to see it. Click any row for its evidence — the raw flows, Zeek sessions and DNS queries inside the window.

Normalize this pattern

What it is. A feed of near-similar traffic — flows and DNS — that you read the way you read a log. Select the rows that are normal for this network and press Normalize.

What normalizing does. The pattern is added to that host's adaptive baseline, permanently. Its statistics widen to include the traffic, so the models stop finding it anomalous. Nothing is muted: there is no suppression list, and the alert path never reads this decision.

What it does not do. It does not hide the traffic. Rows stay in every view; the feed marks them green so you can see what you have claimed.

Undo. Remove an entry below. The pattern leaves the baseline at the next retrain and the decision is kept in the record.

Ripple patterns. A ripple signature is narrower than a baseline entry: one exact value (a TLS name/fingerprint pair, a user-agent, an SSH banner pair), on one host and one channel. It does not hide the host or the channel — the same value from another host, or a different value from this one, still ripples. It expires on its review date (90 days by default), and removing it brings the evidence back on the next pass.

Overview

What it is. Five detectors watch the same traffic with different methods — Isolation Forest, its Gradient Boosting student, a k-nearest neighbours (KNN distance) detector, a local outlier factor (LOF) detector and an adaptive per-host baseline — and the ensemble asks how many independent families agree before a score is believed. Isolation Forest and Gradient Boosting are one family; KNN distance, LOF and the baseline are three more. Whether a detector contributes is derived in the Detectors table below — a training row, an artifact on disk, a measured false-alarm rate against its target, and the model card's veto. No stored status word is repeated as a fact here.

What is new. Calibration and the shadow channels below are read-only experiments: they measure budgets, candidates and regime changes, but no shadow row can create or change an alert.

What writes it. Each retrain folds in the newest samples from this deployment's own traffic.

Last changed. Check freshness above — a model scored against a stale baseline is still confident.

Where to see it. Training history, score distribution, agreement, features and near misses all live below.

Training history samples per retrain

What it is. Each line is one detector over time. The sampled detectors draw from a 72h training window every 6h and the line shows how many rows they sampled, capped at 80k (Isolation Forest), 40k (Gradient Boosting) and 5k for k-nearest neighbours (KNN distance) and local outlier factor (LOF), each on its own 19-column reference — a flat line means the window is already full.

The Adaptive Baseline is a different quantity. It rebuilds per-host baselines from the last 24h on every detection cycle, so its line is the number of HOSTS it just baselined (tens, not thousands) and it has far more points than the others. It is on this chart because its age belongs beside theirs, not because its y-value is comparable.

What writes it. Every retrain, whether cadence or operator-triggered.

Where to see it. This chart, and the freshness note on the Models card above.
