Connection graph

What it is. The connection graph: a dot is a host both weirlings saw traffic for, a line is a conversation between two, thickness by bytes. The dashed rings are hop distance from the reported IP TTL — no ring means the TTL was not measured, never that a host sits outside the network.

What writes it. Netflow edges from every weirling in the window; Zeek enriches them where it runs.

Last changed. Redraws with each refresh; the window pill above names the range.

Where to see it. Click a dot for that host's conversations, a line for its exact source → destination, and use the tables below when the answer needs to go into a ticket.

The adaptive baseline

What it is. A per-host picture of normal: each host's own average and spread of bytes, packets and destinations over the training window. A fixed threshold cannot know that one host normally sends a hundred times more than another; this baseline does.

What writes it. The Adaptive Baseline detector, refreshed every detection cycle; the table shows its latest snapshot per host. Behavioural (Zeek) baselines and fingerprint history join the volumetric ones when both sensors observe the same host.

Last changed. Every refresh — the line above says how old the newest snapshot is. A stalled refresh count is visible here instead of silent.

Where to see it. This table; and any anomaly the baseline helped score carries its name under Models on the row.

Last changed. Every block and expiry is an audit row.

Weirlings

What it is. A weirling is any sensor feeding this hub — a box running its own capture, or one exporting flows here. Registering records the expectation, so 'the sensor you added never reported' can be told apart from 'you have no sensors'.

What writes it. Registrations made here; heartbeats sent by each sensor.

Last changed. Heartbeat age updates continuously on the fleet table.

Where to see it. The state column — register, enable, revoke on each row.

Weirling

Sonar surveys the network this sensor's capture interface is on — it reads the segment, sends one ARP sweep to find which addresses answer and which are free, checks the gateway — and reports what it measured. Nothing is written; enabling siphon uses what Sonar found when it runs.
A test run switches the sensor to siphon mode for 30 seconds, lets the worker run the real intercept, then switches back to loch — the mappings are restored on the worker's normal shutdown path. It needs the siphon capabilities on the sensor node and a complete plan. The result below says which hosts were intercepted, and that the mode was put back.

Intercept plan for this weirling

What it is. The plan the sensor itself will run, stored on its own registration: its mode (loch, or siphon for in-path), and for siphon the capture interface, the segment, the address it borrows, the gateway whose hosts are relayed, and the targets.

What writes it. The operator, here.

Last changed. The sensor reads its own row every half-minute and arms or disarms itself.

Where to see it. The sensor's own state column, and its log.
