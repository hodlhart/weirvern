This is the DEEP check — it reads ClickHouse, so it answers "is data flowing". The Kubernetes liveness probe deliberately does not, because a probe that fails when the database is slow would restart the GUI and hide the real problem. The two are different questions and this page asks the first one.

Settings

loading…

These are the values the running deployment is using, read from the cluster. Each setting is shown as the control that changes it — a toggle for on/off, a dropdown for a choice, a bounded number for a number — with a ? beside every row explaining what it does and what happens when it moves. Who may change a setting depends on the account you signed in with: admins can stage and apply changes, and viewers see every value read-only. Secrets show as (set, N chars) or (not set), never in value. To change values without a web account, use weirvern config set or the TUI, then apply.
